Product Requirement Document (PRD)
Project Name: Managent (MVP)
Document Version: 1.0

Author: Startup Founder

Target Release Date: Q3 2026

Product Epigram: The Network Firewall and Control Plane for the Autonomous Workforce.

1. Executive Summary & Product Vision
Managent is an open-source and cloud-hosted Model Context Protocol (MCP) Tool Gateway. It serves as a secure reverse proxy and firewall sitting between autonomous AI frameworks (e.g., CrewAI, LangChain, Cursor) and internal or third-party enterprise tools (e.g., Stripe, HubSpot, SQL databases).

Instead of relying on unstable, probabilistic text prompts to secure agent behaviors (e.g., telling an LLM "never refund more than $100"), Managent enforces deterministic, byte-level security at the network layer, parsing and validating JSON-RPC tool payloads before they execute.

2. Target Audience & User Personas
Persona A: The AI Application Engineer. Builds autonomous agents using Python/TypeScript frameworks. Frustrated by writing complex logic to manage environment credentials, limit checking, and custom tool validation blocks.

Persona B: The Engineering Team Lead / CTO. Wants to leverage the efficiency of autonomous agent fleets across their company but is completely blocked by security anxieties regarding data leaks, api rate-limiting, and runaway token billing loop costs.

3. Core MVP Feature Requirements
Module 1: Ingress Layer & Protocol Handling (Northbound)
Requirement 1.1 — Remote MCP Protocol Compliance: The gateway backend must ingest incoming connections over HTTP with Server-Sent Events (SSE) transport layer, adhering strictly to the official open-source Model Context Protocol specifications.

Requirement 1.2 — Unified Tool Multiplexing (Federation): When an agent sends a tools/list request, Managent must fetch tool definitions from all registered target systems, aggregate them into a clean, namespace-protected directory, and serve a single unified tool schema file back to the agent application.

Module 2: The Firewall & Policy Core (Validation Engine)
Requirement 2.1 — Structural Parameter Validation: The proxy engine must decode incoming tools/call JSON-RPC bodies and run explicit type and value checks on arguments within microseconds.

Requirement 2.2 — Rule Execution Manifests: The core firewall must support conditional routing logic stored inside a fast, in-memory data store (Redis).

Example Condition: if tool == "stripe__issue_refund" AND arguments.amount > 100.00 -> REJECT/PAUSE.

Module 3: Human-in-the-Loop (HITL) Stream Controller
Requirement 3.1 — Stateful Socket Holding: When a high-impact rule condition is met, the proxy must physically hold the HTTP long-poll request open without timing out, creating a "frozen network execution state."

Requirement 3.2 — Asynchronous Interactive Webhooks: The proxy must instantly dispatch an interactive layout payload block to a configured corporate Slack channel displaying [Approve] and [Deny] buttons.

Requirement 3.3 — Stream Resumption: * If a human clicks Approve, the proxy unfreezes the socket pipeline and passes the payload downstream.

If a human clicks Deny, the proxy terminates the request and falsifies a structured JSON-RPC error response block back to the agent application.

Module 4: Security & Credential Isolation
Requirement 4.1 — Virtual Token Swapping: The client application must only hold a short-lived bearer token issued by Managent (mng_live_xyz).

Requirement 4.2 — Server-Side Header Injection: Real enterprise production API keys must live completely encrypted within a secure server environment vault. Managent will strip the proxy token and stitch the real key into the HTTP headers only at the split second the validated request passes onto the live internet toward the target API endpoint.

Module 5: Observability & Admin UI
Requirement 5.1 — High-Throughput Activity Ledger: Every tool attempt, parameter block, timestamp, and rule evaluation must log instantly to an immutable audit ledger database (e.g., ClickHouse).

Requirement 5.2 — Single Pane Management Interface: A web dashboard providing a clean workspace to manage registered tool connections, toggle security policies, and review running agent audit histories.

4. Non-Functional & Technical Specifications
Language & Stack: High-performance, low-overhead compiled language (Go or Rust) for the core gateway routing engine to minimize latency overhead to sub-5 milliseconds.

State Management & Caching: Redis for active session context mapping and ultra-fast policy rule lookups.

Protocol standard: Strict adherence to JSON-RPC 2.0 specifications wrapped in the Model Context Protocol framework schema.

Deployment: Containerized via Docker / Kubernetes to allow enterprise clients the choice to deploy as a managed cloud option or self-hosted on-premise infrastructure behind their private networks.

5. Success Metrics & Validation Strategy
To validate Product-Market Fit with your early landing page users, the MVP metrics will focus on:

Proxy Latency Overhead: Total execution delay added by Managent processing the rule logic must remain under 10ms per tool call request.

Jailbreak Resilience: 100% block success rate on invalid parameter inputs, completely ignoring any linguistic manipulation attempts happening inside unproxied LLM frameworks.

The User Activation Metric: A beta tester registering at least 2 distinct tools (e.g., Database + Slack) and executing over 100 successful proxied tool calls within their first week of integration.
